# Voice frontier refresh: Azure-only clone quality

Research date: 2026-10-09. This is a read-only review of public primary sources and the repository's September 30 handoff, state, and voice rejections. No audio was uploaded, no model or vendor endpoint was called, no image was built, and no Azure or other cloud resource was changed. Vendor and project measurements below are claims from their publishers, not Vyakti results.

## Current evidence boundary

Vyakti's live private pilot is `ResembleAI/Chatterbox-Multilingual-hi` V3 on an Azure GPU. It exposes one fixed Hindi/Hinglish sample. There is no fresh owner-likeness result, no matched English result, and no realtime acceptance result. The earlier reference-bandwidth defect was repaired, but bandwidth is only an input diagnostic. It is not evidence that the clone sounds like the owner.

The primary-source freshness check changes one material item since the September 27 review: ElevenLabs released Eleven v4 and v4 Turbo on **2026-09-28**. The official changelog says v4 improves cloning across 90+ languages and v4 Turbo targets realtime use, but the separate private-deployment page still says Azure is planned for later in H2 2026 and currently names only v2/v2.5 for private TTS. Therefore v4 is a current quality reference, not an Azure-eligible experiment today. [Dated Eleven v4 changelog](https://elevenlabs.io/docs/changelog/2026/9/28) [Private deployment](https://elevenlabs.io/docs/overview/capabilities/private-deployment)

Other dated heads remain: Cartesia Sonic 3.6 snapshot `2026-08-27`; Chatterbox V3's source release on **2026-06-10**; Qwen3-TTS on **2026-01-22**; and Fish S2.1 Pro in June 2026. No primary source reviewed on October 9 establishes a later Fish speech model, Cartesia model, Chatterbox multilingual model, or Qwen3-TTS release. Moving documentation and fresh search indexing were not treated as release dates. [Sonic snapshots](https://docs.cartesia.ai/build-with-cartesia/tts-models/latest) [Chatterbox V3 commit](https://github.com/resemble-ai/chatterbox/commit/65b18437192794391a0308a8f705b1e33e633948) [Qwen3-TTS release record](https://github.com/QwenLM/Qwen3-TTS) [Fish models](https://docs.fish.audio/developer-guide/models-pricing/models-overview)

## The two experiments to run next

### 1. Isolate reference quality from the Chatterbox model choice

Run three sealed arms on the existing Azure path: A, the exact deployed Hindi V3 pack with the currently admitted reference; B, the same Hindi pack with a newly admitted clean wideband reference; C, Multilingual V3 with the same new reference and exact V3 loader. This is the highest-value experiment because it can tell whether the remaining failure is reference admission, Hindi specialization, or the model family without changing architecture.

Use 18 held-out prompts, six Devanagari Hindi, six mixed-script Hindi plus English, and six Romanized Hinglish. Generate two fixed seeds per arm: **108 scored clips**. Preserve the original reference bytes; do not run speaker separation on a single-speaker recording; never deliver the 16 kHz scoring copy to the model. Seal reference hash, transcript, measured spectrum, clipping, SNR, model and companion hashes, input transform, language ID, effective CFG, seed, GPU SKU, and output hash.

### 2. Close the English and realtime gap with Qwen3-TTS 0.6B Base

Build no cloud resource until the pinned local manifest proves an offline dependency closure. Then compare Qwen3-TTS 0.6B Base against Chatterbox Multilingual V3 on the same clean English reference, reviewed reference transcript, exact English prompts, and fixed seeds. Use 12 held-out Indian-English prompts covering explanation, questions, names, numbers, abbreviations, emotion and short dialogue: two arms by 12 prompts by two seeds, **48 scored clips**. Qwen is an English experiment only; sending Hindi or Hinglish to an unsupported official checkpoint would not be a fair failure test.

For the Qwen arm, separately measure three cold starts and at least 30 warm requests at concurrency one. Record request acceptance, first generated packet, first playable non-silent browser audio, final audio, RTF, peak allocated/reserved VRAM, cancellation-to-silence, failures and total allocated GPU seconds. The published 97 ms number is only a hypothesis to test.

## Shared acoustic and listening protocol

Acoustic checks are diagnostics, never “percent cloned.” Report human-verified transcript WER/CER by register; name, number and switch-boundary errors; duration and pause alignment; speaking-rate error; F0 and energy contours; clipping and bandwidth; and speaker-embedding scores calibrated against owner-vs-owner and unrelated-speaker controls. A bandwidth or embedding score cannot promote an arm.

Blind randomized listening must include the consenting owner plus at least four Hindi-English listeners familiar with the owner's real voice, held-out natural owner speech, and an unrelated-voice control. Rate owner identity, Indian accent authenticity, naturalness, prosody, Hindi pronunciation, embedded-English pronunciation and switch continuity on separate five-point scales, followed by forced preference and “recognizable without the script.” Report owner ratings separately, paired uncertainty, failures and both seeds. Do not name a vendor winner from one owner.

Advance only if the owner accepts the voice, median likeness is at least 4/5, no supported-register median is below 3.5, names and numbers have no material omissions, and the selected realtime arm reaches warm p95 end-of-turn-to-audible at most 1.2 seconds and p95 interruption-to-silence at most 250 ms in the real browser path. These are proposed gates, not current measurements.

Every run must record gross Azure GPU/CPU seconds, cold-start and idle tail, build time, storage, generated minutes, accepted minutes and retries. Report gross cost per accepted audible minute and credited consumption separately. A new run also requires fresh owner voice consent and a predeclared Azure spend ceiling; the existing USD 1 application ledger remains a planning guard, not a provider billing cap.

## Decision

Do not switch providers. First run the sealed Chatterbox reference/model split. If a clean reference cannot clear owner likeness, Qwen 0.6B is the next bounded English/realtime experiment, while IndicF5 stays a deferred Hindi challenger. Eleven v4 and Fish S2.1 are excluded by Azure-only serving; Cartesia Sonic 3.6 remains promising but procurement-gated; Indic-Speak cannot clone; Jugnu is a useful low-cost control whose own authors identify voice identity as its weakest axis.

This review adds no voice-quality result and makes no vendor leaderboard claim.

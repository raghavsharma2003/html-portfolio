# Person Model and calibration review scope

The old mounted review screens could show replica A's claims or calibration after the owner switched to B, then submit an approval for B using the stale displayed version. Both actual components were mounted without replica keys in the Studio caller, and their async reads, mutation readbacks and auth-error callbacks had no scope fence. The retained old-source browser control demonstrates A's display followed by a POST containing B and version7.

Only `src/studio/PersonModelStudio.tsx` and `src/studio/CalibrationStudio.tsx` change production behavior. Each token/replica pair now owns a distinct mounted review scope. Scope cleanup prevents late reads, write completions, readbacks and401 callbacks from affecting a new replica/account or a page the owner has left. Read generations reject superseded reads; successful status responses must name the requested replica. Approvals require the current displayed draft version, and a synchronous mutation lock prevents overlapping explicit writes. Current-scope failures remain visible and recover through an explicit read Retry; no POST or generation is automatically retried. Server SQL, consent, model and identity/voice authority are unchanged.

Our fixture checks those passed bindings and prompt selection, not PostgreSQL locking or live cross-user isolation.

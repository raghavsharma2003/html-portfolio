# Explicit private teaching refinement

Separate candidate from checkpoint43230e5e. The private result previously had no caller that could adjust a compiler-supported teaching field and test it again. This backend adds GET/POST `private_refinement` to the existing authenticated teacher-sheet endpoint. The companion UI is a separate isolate. Existing save_draft, publication, runtime feedback, model dispatch and frozen native probe bytes remain unchanged.

The one writable field is explanationOrder. The owner reviews its current value, actual draft content hash, stored version and private epoch, then explicitly saves a value or explicitly clears it. Only an existing explicitly owned draft attached to an actual completed private request is eligible. Published, validated, revoked, unavailable, foreign or incomplete targets are refused. The actual private request reader checks receipt, current source/evidence and encrypted answer eligibility; its answer bytes are not returned by the refinement endpoint.

The write patches one JSONB key, preserves every unrelated field and stored version, and rotates private_text_epoch. It compares the reviewed whole JSON and epoch, validates the updated draft with the actual private compiler, and never generates an answer. Lock order is source, replica lock-only, completed request, direct replica epoch comparison/increment, then exact draft update. A request row lock is necessary because withdrawal intentionally leaves the replica epoch unchanged. Receipt liveness is also a SQL predicate. No migration or new retention table is needed.

GET `/api/teacher-sheet?op=private_refinement&replica_id=<uuid>&request_id=<uuid>` returns `{refinement:{replica_id,request_id,sheet_id,sheet_hash,sheet_version,private_text_epoch,field:'explanationOrder',value:string|null,updated_at,can_save,blocker?}}`. private_text_epoch is a decimal string. Missing guidance is null. A stale but still completed owned request may return the current field with can_save:false and blocker private_refinement_review_changed; this is readback, not fresh write authority.

POST `/api/teacher-sheet` accepts `{op:'private_refinement',replica_id,request_id,sheet_id,expected_sheet_hash,expected_private_text_epoch,field:'explanationOrder',value}`. Value must be nonempty after trim, at most4000UTF16 units, and contain neither prohibited control characters nor malformed surrogates; it is otherwise preserved exactly. Explicit removal uses clear:true with value absent. Missing both, clear:false, or clear:true plus value refuses400. Clearing an absent field or saving identical text refuses private_refinement_no_change. The actual compiler may additionally reject a proposed value when total existing draft core exceeds its existing bound.

Successful POST returns the same current-field shape with saved:true, a new sheet hash/epoch and can_save:false because the old result is now stale. A changed reviewed draft/request returns409 private_refinement_conflict. A failed/ambiguous SQL request returns503 private_refinement_save_uncertain. Never automatically retry POST. GET readback after an uncertain write can truthfully show the current saved value and hash; it is not a mutation-specific receipt. If the old hash and can_save:true remain, the owner may explicitly retry after review. After a successful edit or observed current-state change, refresh readiness and require a fresh explicit question with normal private attestations and budget.

User-facing outcome is Saved to private draft after a successful receipt. Uncertain readback should say the private draft currently contains the guidance. Do not claim learning, dataset training, answer improvement or factual evidence adoption. Clearing removes the current draft field, not earlier encrypted private answers. Those retain existing explicit test/source/AI erasure controls. This feature adds no new historical store, publication or persona adoption.

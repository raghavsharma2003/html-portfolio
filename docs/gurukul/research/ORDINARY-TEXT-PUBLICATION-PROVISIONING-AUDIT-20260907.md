## Which gates can be separated, and which cannot be silently relaxed

The existing teacher floor **already permits consent to text while refusing voice** (`docs/gurukul/safety-floor-teacher.md:86-101`). Thus requiring a ready voice/genome/fidelity verdict merely to create the text agent is an implementation coupling, not an unavoidable text-lane requirement in that document.

However the same floor requires a verified named principal, licensed likeness/assets, audience, subject scope, term and revocation. The full runtime's verified identity/training/voice promises are legitimate for that capability. The modern composite implementation plan still lists missing visual/document/recording-authority services. This audit found no alternate current receipt that could honestly establish those successes. Do not change full-runtime predicates or reinterpret old grants to make text publication green.

There are consequently two distinct public promises:

1. **A verified teacher's text likeness.** Voice can be optional under a new text-specific capability, but real principal verification and a genuine text-publication receipt still must exist. Current code cannot provide this ordinary path while its verification producers remain unavailable.
2. **An account-published assistant using explicitly released materials.** This can be designed without a verified voice or real-person likeness claim, but it is a new, narrow publication authority and disclosure policy. It cannot reuse the verified-clone badge, first-person biography, face/voice, or the claim that a named real teacher's identity has been verified. Account authentication proves control of the publishing account only. This policy distinction must be explicit before implementation; “easy expert flow” is not evidence of identity or source rights.

The recommended earliest public-value slice is option2 if root adopts that clearly labeled product contract. Continue the existing private test loop regardless. If the product must promise a verified named-person clone on the first public link, option1 is the honest boundary and public publication remains waiting on us until verification is real. Neither option needs mandatory twelve-row fact editing; typed knowledge stays an optional experiment.

## Smallest complete account-published text slice

Use the existing Feed -> Meet -> Share UI. After an optional private test, the owner chooses one existing canonical text/document source and reviews the public teaching projection, source scope, AI disclosure and permitted audience. One explicit final Publish text link action authorizes exactly that version; private test success is not a prerequisite or a grant. No voice enrollment, personality-claim review gauntlet, automatic mining adoption or mandatory structured-fact table is added.

The server needs a versioned **public-text-only publication record/receipt**, bound to authenticated owner, existing replica, immutable reviewed profile projection, exact source/item/evidence hashes, lane, audience, term, policy and publication version. Its provenance is account-published material, not verified real-person likeness. Only teaching/manner fields actually approved for public use belong in the projection. Do not copy private autobiographical fields, memory, conversations or private rehearsal answers automatically. Current teacher domains remain physics/chemistry/maths until a separate supported-domain expansion.

Final POST must use a server-reviewed content hash and compare-and-swap the same version inside SQL, creating the real receipt and publication atomically. Same intent/version replay reads the existing result; conflicting or lost responses require readback and a fresh explicit review, never automatic republish. Publishing a replacement keeps a private successor separate and does not silently follow subsequent draft edits. Source changes/removal or permission revocation make the linked snapshot unavailable pending explicit review. Slugs/public identifiers must not attach one principal's old conversations to another.

**Do not pre-create a full-runtime agent or mark the existing sheet published to borrow its loader.** Those states unlock old readers that know nothing about the narrower permission. The bounded safe implementation uses a dedicated text-publication resolver/capability keyed to the existing replica, with a web-only text handler. It can share the app's Share entry, visual shell, disclosure/gate primitives, Azure adapter and provider ledger without manufacturing `vy_replica_runtime_capability`, approved person/voice profiles or a sheet consent UUID. Existing Room/full-runtime loaders and publish gates remain unchanged. This adds a mode inside the product, not a second general agent platform.

The text compiler must accept the new server-verified publication projection and describe its real provenance; it must not reuse the private compiler's owner-only authority object for visitors or the public compiler's legacy consent-column basis. Reuse escaped material, explicit language precedence, evidence boundaries, no unavailable tools, and full shared output gates. Keep source content untrusted as instructions. Guest answers must not reveal the owner's private relational memory or suggest that the owner saw a message.

Visitor authorization is a separate missing caller: the existing private rehearsal store requires the owner and its one-question receipt, so it cannot be called under the publisher's identity on behalf of a visitor. The new handler needs publication-current checks at admission and immediately before delivery, visitor/session scope, app-level disclosure before the first answer, the existing age/audience safety behavior, bounded quota/rate admission and its own idempotent question identity. Reuse Room algorithms carefully: its current quota SQL is bound to Room rows and cannot simply accept another table's UUID. No voice, telephony, messaging publication or continuity promise in this first web-only scope. A share link is not permission to bypass audience/guardian requirements already enforced by the product.

Pause, withdraw, source deletion and replica erasure must revoke public-text serving structurally, including pending completions and caches. Every copied source/profile payload needs exact owner/source lineage and export/erase coverage. Content disposal must not erase settled provider usage or claim a refund. Current source/replica erasure and private epochs are useful patterns, not proof that a newly introduced publication copy is covered. A complete migration/reader/writer/erasure contract would be the next implementation proposal, not an action taken in this audit.

## Proof before exposing the link

- Source/caller negatives: ordinary unverified owner cannot obtain a full runtime, verified identity badge, voice authority, training grant or legacy published sheet by taking the new path. Passing account receipts or a private request ID to publication must refuse. No producer or consumer may treat a client-supplied consent UUID as authority.
- Actual owner UI: Feed one permitted document -> minimal private draft/test -> explicit Share review -> final publish -> matching readback -> second browser/account text question. Cover390/1440, changed selection, another owner's source, missing prerequisite, lost POST, refresh and explicit unpublish. No automatic grant or model call on navigation.
- Real isolated SQL: exact reviewed version/owner/source/receipt binding; competing publication intents; source removal/permission withdrawal versus admission and completion in both lock directions; old-snapshot negative; copied payload cleanup; visitor separation; no unrelated owner mutation. EXPLAIN alone is insufficient behavior proof.
- Fresh bounded Azure: correct approved source facts, unsupported-question uncertainty, EN/HI/Hinglish, an identity question that does not invent verification, source injection, late never rules, stale-before-delivery withholding and honest settled/uncertain billing. No typed-knowledge experiment needs to be bundled into this public-path proof.

**Decision / reversal:** separate text publication from voice capability, while preserving genuine identity/likeness promises. Start with an explicitly account-published material assistant only if its narrower provenance is accepted; otherwise keep public sharing blocked until the verified-principal producer works. Reverse or pause the new mode if users mistake it for the verified person, private facts escape, revocation/cost control fails, or the added mode fragments the actual journey. Private rehearsal stays usable. No completed publication, verified owner, legal compliance, user-quality or full-product claim follows from this source audit.

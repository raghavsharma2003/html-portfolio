## Implemented, with an actual caller

`api/_liveness/issued-contract.js` builds and validates a distinct nonservable modern commitment. It binds owner/replica/challenge/subject, identity case and source hash, selected primary source/hash/selection epoch, reference evidence hash, capture/storage/comparison consent IDs and comparison receipt hash, exact locale/bank/item/phrase/nonce, profile and ten-minute validity. Validation requires an independently held expected hash, rejects extra/accessor fields, and reconstructs the registered phrase. No existing VoiceGenome is required for first enrollment. Existing unreviewed Hindi/English sentence banks, evidence profile and nonce parser are reused without claiming review or calibration. Existing legacy contract/schema remains unchanged.

`api/_liveness/azure-shared-audio.js` composes existing signed `identity_audio_v1` derivation and existing Azure Speech `transcribeBytes`. It binds returned capture/canonical/speaker hashes, snapshots the private bytes, compares the two speaker embeddings only at compatible pinned model/VAD revisions, and verifies the actual 24 kHz source to 16 kHz ASR transport commitment. Four server-authority reads surround the operations. It checks cancellation and caller mutation and rejects changed commitments, reference evidence or expired authority. Azure-only serving applies even if deployment strict mode is unset.

The output is content-free, nonservable partial evidence: exact byte/transport commitments, literal nonce match and measured per-family cosine. It has no transcript, vector, locator, identity verdict, synthetic-risk score or speaker-continuity score. A nonce match does not mean the sentence was read or that a person passed verification. Reviewed phrase acceptance remains explicitly missing. ASR confidence and duration-based evidence confidence are not promoted to liveness measures.

`api/_liveness/registry.js` is the actual integration: the configured modern verifier used by `/api/replica-liveness-sweep` now goes through the composer wrapper. Its production authority loader deliberately throws `liveness_issued_capture_unavailable` before adapter construction, private reads or external work. Even an injected fully composed partial result throws `liveness_issued_capture_composite_evidence_unavailable` before the existing verdict and settlement functions. No fallback to the old remote composite transport occurs. Missing-contract rows follow the existing content-free retry/expiry lifecycle. `modernCaptureReadiness()` remains false; owner status/cancel and existing supported legacy paths are unchanged.

This implements a contract, composer and production refusal caller. It does **not** implement SQL issuance, persisted authority loading, successful enrollment, ownership proof or settlement. The injected authority port is a test/next-implementation seam, not consent from an HTTP body or an environment switch.

## SQL issuance/CAS proposal, not implemented or authorized for execution

Actual top-level migration inventory ends at `143_text_publication.sql` (140 selection epoch, 141 rehearsal, 142 cancellation). No migration number is reserved here. `vy_replica_biometric_verification_grant` already has `statement_set`, `receipt_hash`, `receipt_payload` JSONB, expiry/state and a challenge/owner/replica FK; therefore a new table is not required merely to store a contract. A targeted constraint migration may still be warranted after a reviewed final persistence schema. Do not inherit the old migration039 DO-block pattern.

1. **Issue:** define a new explicit comparison statement set and owner tap, with exact selected reference shown. Load the selected source and independently stored speaker-evidence artifact under current capture/storage consent, including evidence/model revisions. Select the exact identity case/source. Lock in the documented source/replica/challenge order shared with mutation paths; compare `primary_selection_id`, selected source ID/hash, evidence hash and consent receipts in the inserting statement. Save the modern envelope/contract hash inside the new grant receipt payload with the canonical receipt hash, not a rewritten old grant. Bank/locale/nonce/profile come from server-controlled registries and exact owner language choice. Do not make serving ready just because this inserts successfully.
2. **Lease/authority loader:** project that persisted envelope and independent expected hash into an internal authority object. Independently check grant statement set/hash/state/expiry, exact lease token/attempt/expiry, owner/subject/replica policy, primary selection/source/hash, evidence artifact/provenance/revisions, identity source/case, capture source/hash/lineage and live scan/quarantine receipts. Missing old fields are unavailable, never inferred. Return a private reference envelope `{source_id, source_sha256, model_revisions, embeddings}` only after these predicates. Current composer hashes this entire envelope. Capture source ID is allocated after issue, so the loader must bind it through the persisted challenge/source relationship, not accept it from the caller.
3. **Settlement:** require the same issued contract/hash and authority tuple in the final conditional write, with fresh revocation, selection, source and lease predicates. A complete versioned composite evidence producer is still required; the new partial output must remain ineligible. SQL cannot create missing visual/anti-spoof calibration. Replacement issuance must not retire a still-valid challenge if its replacement insertion fails.
4. **Erasure:** include new references in existing owner/source/challenge erasure and `relcheck` reach. Avoid a separate store of raw audio, transcript or embeddings in grant/audit JSON. Reissue/revoke/expiry must cancel in-flight authority; exact storage/provider cleanup receipts remain mandatory. Preserve the unrelated owner's current reference and other relationships.

Review acceptance before execution: one statement per request with explicit UUID casts; real EXPLAIN; real two-session witnessed primary-switch, source-revoke, consent-revoke, lease takeover and ID-case mutation versus lease/settlement. Assert zero passed/biometric writes on every loss; verify failed replacement leaves the prior challenge intact; check exact cleanup. Mock SQL is insufficient. The new owner consent/UI and persisted authority implementation are subsequent work, not promises made by this slice.

## Provider wall and next acceptance

Current broker Face session routes still do not implement the required same-capture speech/visual continuity and calibrated synthetic-media verification. Face QuickLink plus a separately recorded phrase is not a shared capture. Exact-primary comparison permission, embedding cosine and a matching nonce do not establish ownership. A genuine provider contract must bind the same visual/audio timeline, identity reference, source and issue; include calibrated replay/impostor/dubbed/off-screen/multi-speaker/synthetic attack evaluation across target devices/languages. No threshold has been invented here.

Only after that producer, persisted authority, genuine owner enrollment/reference and protection are accepted should the bounded Hindi/Hinglish/English listening experiment proceed. No owner likeness or fine-tune acceptance follows from these controls.

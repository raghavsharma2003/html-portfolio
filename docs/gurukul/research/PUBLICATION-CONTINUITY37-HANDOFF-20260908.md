Owners can explicitly choose v2 optional continuity while reviewing a new publication. Existing v1 contracts, statements and memory-free behavior remain supported. Visitors see the policy and an optional memory choice once at entry, then control it in conversation settings. Settings come from the server, scoped to authenticated visitor/publication, including before admission renewal. There is no per-answer consent checkbox.

The existing text-publication endpoint now exposes `memory_settings` and `set_memory`; v2 joins include the expected memory policy hash and epoch. Settings changes use compare-and-set, invalidate admission, and return one rejoin step. Confirmed changes clear the old UI receipt; ambiguous changes retain it until server readback. A valid renewed admission can receive a content-free `withdrawn` receipt for an older memory epoch with its original billing state. It never redelivers that text or purchases another generation.

The existing encrypted request store supplies up to three prior whole exchanges, newest first for selection and chronological for the compiler, with at most3000 decoded UTF-16 content units across both questions and answers. Older exchanges outside that window are not included. A newest single exchange exceeding the bound is an explicit unavailable error, never a silently empty record.

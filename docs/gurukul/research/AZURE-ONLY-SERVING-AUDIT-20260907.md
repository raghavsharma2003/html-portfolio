## Small next patches and gates

1. Make Azure-only a shared leaf-enforced policy. Reject forbidden provider selection and non-Azure origins before request dispatch. Cover deceptive hostname suffixes, userinfo, redirects and arbitrary configurable endpoint escape routes. An Azure hostname is hosting evidence, not proof it belongs to the owner's subscription; require deployment inventory binding when accepting a configured service.
2. Replace reachable selection fallbacks first: shared reply, claim extraction, embeddings, uploaded-source ASR and live ASR. Leave unconfigured capabilities visibly unavailable. Preserve relational data and deterministic recall on embedding absence; do not manufacture a vector or grounded response.
3. Repair the voice challenge's direct Sarvam construction separately, preserving hash-bound inputs, transcript-required anti-replay, retry states and provider identity in receipts. Assert that configuring only a Sarvam key cannot enable challenge serving.
4. Gate leaf constructors as well as registries. Exercise real factories with injected network spies, including missing Azure fields and Azure failure; assert zero non-Azure dispatch and one named unavailability result. Keep positive tests for permitted Azure and Azure-hosted openweights.
5. Preserve vendor erasure access for historical objects: `_voice/registry.js:187-207` intentionally allows stored ElevenLabs profile deletion even when serving arms are disabled. A serving ban must not strand biometric erasure obligations.
6. Add an inventory gate for all runtime model egress, with explicit distinction between serving and erasure. Static string scanning alone cannot catch configurable endpoint or redirect escape paths and cannot prove callers run. Pair it with factory and route tests. Existing full release and context gates remain required after the repair; this audit adds no release or quality pass.

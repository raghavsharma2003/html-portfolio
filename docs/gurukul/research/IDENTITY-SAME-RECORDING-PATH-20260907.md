# Identity challenge: one recording for both checks

7 September 2026. Read-only source audit of the integration worktree. This refines the [Azure identity migration draft](AZURE-IDENTITY-MIGRATION-20260907.md); it does not implement or validate identity verification. No recording, model, cloud, database or native decoder was exercised. Root owns context logging. Concurrent reference-version predicate work is outside this audit.

## Finding and recommended path

There is no existing endpoint that proves a challenge's separately uploaded WAV is the audio of its capture video. The smallest connected extension is a **new identity-only operation on the existing private voice-evidence service**: verify the capture bytes, decode one canonical audio representation, compute speaker evidence from it, and return that audio with an authenticated transform binding. The challenge verifier then submits those same canonical bytes, through a deterministic transport derivative, to Azure Speech. The independent client WAV supplies neither speaker nor nonce evidence for the new policy.

This preserves the current sweep caller and authenticated service transport. Moving decoding into the Azure processing worker is possible, but that worker currently has no voice-challenge caller; it would add worker routing and scheduling work as well as the transform itself.

## Minimal implementation plan, not existing functionality

1. **Add one operation to the existing signed service.** A proposed name is `identity_audio_v1` on `POST /v1/analyze`; it does not exist today. Accept exactly one capture byte input and an opaque, server-authored challenge-contract hash. Keep account/person IDs, expected sentence, nonce text and transcript out of the service. Existing source ownership and active-consent checks remain in the application. Validate bytes and size before decode or embedding work.

2. **Decode conservatively and once.** Use ffprobe/ffmpeg already in the image, with bounded local temporary files, no network protocols or external references, fixed decoder arguments, subprocess deadline and output-byte cap. Admit only tested capture containers/codecs with one unambiguous audio stream; reject absent/multiple audio streams instead of selecting whichever yields a match. Measure decoded frame count and reject audio over 30 seconds. Do not use `-t 30`, trimming, padding, denoising, separation, voice replacement or an owner-selected crop to make an overlong or mismatched recording pass. Define timestamp/stream handling in the versioned transform and test it. A capture with video still requires its separate visual/liveness rules; audio derivation alone does not prove lip synchronization or that the video is live.

3. **Make canonical PCM the common parent.** Serialize the complete admitted audio to 24 kHz mono PCM16 WAV, then compute evidence from those exact serialized bytes through the existing speaker path. That path may resample to 16 kHz for its models; the ancestry remains canonical WAV to speaker input. Return the canonical bytes, SHA, byte size, sample rate/channels/format, exact frame count/duration, parent capture SHA, selected stream, transform/version/parameter commitment, actual decoder version and actual embedding model revisions. Put the opaque challenge-contract hash in this same response. The existing HMAC authenticates the envelope. Do not label a transform string as an immutable executable digest; deployment-image identity needs its own verified readback.

4. **Validate the result before ASR.** Add a dedicated adapter method reusing private input and wake/sign transport. Unlike `normalizedMeasurements`, it must preserve and strictly validate the transform envelope and model identities. Rehash returned WAV bytes, parse PCM independently and compare every scalar to the signed manifest and issued contract. Reject unknown transform versions, source mismatch, unexpected streams, missing embeddings or one invalid coordinate. No client-supplied WAV or manifest enters this server-only seam.

5. **Reuse Azure short recognition without fictional storage.** Factor its existing verified-byte/resampling/request logic into an internal routine with explicit canonical-byte input and provenance; keep the ordinary storage-backed wrapper unchanged. This avoids pretending the capture video's storage path contains a WAV that was never stored there. The new verifier calls that routine only with the validated service result and exact issue-time locale, retaining canonical SHA, actual 16 kHz transport SHA and transform identity. Speaker evidence and ASR need not use identical resampling filters, but both must trace to the same exact canonical PCM. Do not send the expected sentence/nonce as a recognition hint.

6. **Carry lineage to settlement.** [`runVoiceChallengeSweep`](../../../api/_replica-voice-identity.js) currently forwards only candidate embeddings, recognized text and two independent input hashes to the decision. Extend the new versioned contract to carry the validated capture/canonical/transport/contract commitments. Persist a compact, content-free manifest and its hash through the existing attempt/challenge basis; preserve the basis size limit. Verify these bindings again against current challenge, attempt, source authority and issued reference at settlement. Do not relabel the old `transcript_input_sha256` silently: version the semantics and require the new lineage fields. Locale/profile/schema changes belong to the parent migration plan; this document reserves no migration number.

Keep canonical/transport bytes ephemeral initially: no new uploaded source or enrollment artifact, no fake storage locator, no promotion into voice training. The existing capture remains an identity-challenge source and follows current erasure fences. Clear temporary files and buffers after success, rejection and failure; a service crash requires bounded ephemeral-volume cleanup. Persist only necessary content-free commitments, not audio, transcript, URLs, signatures containing credentials or vectors. If later persistence is needed, add explicit artifact ownership, source-erasure reach and writer fencing before enabling it.

## Tests and release constraints

These tests are proposed, not run in this audit.

- **Real decoder fixtures:** valid browser WebM/Opus and supported MP4/AAC captures, silence, corrupt/truncated files, no audio, multiple audio streams, unusual timestamps, oversized inputs, 30 seconds and one extra frame. Assert complete decoded duration and temporary cleanup. A decoder fixture containing more than 30 seconds must fail even if its header lies or a crop would pass.
- **Same-recording attack:** capture A with valid independently hashed WAV B must never produce B's transcript. Keep a positive A-to-canonical-A-to-speaker/ASR run. Strike the parent/contract comparison in a negative control and demonstrate that a swapped signed derivative from another request then escapes; the normal implementation must reject it.
- **Transport integrity:** wrong parent SHA, changed canonical byte, wrong frame count/rate, altered manifest, unknown transform, replayed request/response nonce, wrong HMAC, missing model identity and response loss. Assert no ASR call before validation. Changing a storage reference must not supply alternative bytes through the internal seam.
- **Caller and lifecycle:** actual verifier through sweep to decision/settlement, including locale/reference/source/consent changes while work is in flight, cancellation, lease expiry and reissue. Preserve mandatory spoken nonce and thresholds. Provider/decode uncertainty leaves identity closed. Exercise current SQL through real isolated-development EXPLAIN and bounded lifecycle records; fixtures alone do not parse SQL.
- **Regression:** extend existing [`evals/voice-evidence/run.mjs`](../../../evals/voice-evidence/run.mjs), challenge, Azure speech and native-processing suites as appropriate; test old evidence operations and ordinary storage-backed ASR unchanged. Run the complete release gates separately.

Keep Azure-only verification disabled until the complete new profile is implemented and accepted. Do not rebuild/warm a GPU, create a job or change production routing for this document. A protected same-recording pipeline proves input ancestry, not an identity error rate, voice likeness, visual liveness or resistance to every synthetic replay. A bounded authorized real capture pack with impostor/replay controls is still required after deterministic and SQL checks.

# Modern identity composite: concrete staged implementation

7 September 2026. Source review of the current integration tree and three official Azure documentation pages. No code, database, model, provider or deployment action was performed for this plan. The intake and old-erasure helpers remain frozen. This supersedes older notes saying capture decoding and Azure private-Blob intake do not exist; those primitives now exist in source.

The smallest useful implementation is a **modern worker-side evidence composer**, using the existing signed voice-evidence service and Azure Speech byte adapter, with a separate versioned visual-evidence broker operation. It can produce real same-recording speech evidence and exact primary-reference comparison before full identity acceptance is enabled. It cannot honestly satisfy today's numeric continuity/synthetic-risk contract merely by connecting those two services. A bounded visual continuity and anti-spoof component, or a documented SDK-level media binding that provides equivalent authority, remains required.

## Stage 1: versioned modern contract and real audio/reference evidence

Implement a new modern profile in a dedicated api/_liveness/issued-contract.js, reusing canonical JSON and the already built nonce-v2/speech-v2 parser functions where their exact semantics fit. The legacy issued-contract.js has reference_genome_version and remains servable:false; it is not the modern contract. Its stored descriptor still says several prerequisites are pending even though parser helpers now exist, so do not silently reinterpret its hash.

At issue, SQL must bind the exact selected primary source, source SHA, selected_at, required current evidence/artifact IDs and hashes, completed processing revision, compatible speaker-model revisions, exact source consent IDs, ID-case/reference SHA, current replica policy, selected hi-IN/en-IN locale, reviewed bank/item, nonce hash, capture profile and decision version. Prepare the canonical document after an owner-scoped read, then use atomic issue CAS against that exact snapshot; failed preparation must not consume an older challenge. The server selects bank/nonce/profile. UI language may preselect a visible choice, but is not issue authority by itself.

Use existing vy_replica_liveness_challenge and verification-attempt rows for an additive modern issued document/hash and bounded evidence-manifest hash/result. Add explicit nullable reference_source_id/reference_sha256, issued locale/profile/version, or an equivalently constrained single issued document with indexed authority columns. A new migration number must be checked at implementation time; migration 137 belongs to the legacy voice-challenge table and does not add these fields to the modern table. Preserve NULL legacy rows and reject their admission to the new profile. Do not backfill guessed locale, primary reference or Face binding.

Add a narrow modern reference-reader helper. It reads only exact ready primary source plus its committed voice_embedding evidence, latest allowed artifact decisions and real input lineage. Require compatible current model revisions and sufficient independent usable windows. If old rows lack revisions or adequate windows, explicitly request verification-only remeasurement of those same server-selected primary bytes/windows under a new, explicit comparison consent. Never borrow another source, assume old revisions equal today's deployment, or manufacture a reference genome. The current narrow grant's attestations mention live processing and face-to-ID comparison, but do not explicitly bind an enrollment reference. Version the statement set to explain and commit the specific source comparison; do not reinterpret old grants retroactively.

Create api/_liveness/azure-shared-audio.js as an internal composer. Given a validated current lease, it calls identity_audio.derive once for the exact capture and contract hash, then transcribeBytes on the returned canonical body. It validates the ASR input commitment equals canonical SHA and speaker_input_sha256. Compare candidate/reference embeddings with existing pure cosine code, recording family, actual revision, window count and comparison method. Never convert duration confidence or cosine into a calibrated probability. Keep canonical audio, transcript and vectors ephemeral; persist only necessary commitments and result categories. Wrong nonce/reference may produce a real closed rejection without waiting for a missing visual model; successful audio evidence alone is incomplete.

The first implementable acceptance for this stage is an actual modern issue/lease-to-evidence result with a same-recording attack test and exact primary replacement refusal. It does not write passed settlement. It supplies useful real measurements to the next stage rather than returning a blanket provider-unavailable result.

## Stage 2: broker protocol and visual recording authority

Keep orchestration in the modern application worker, where both evidence and ASR adapters already live. Add /v1/liveness/verify to services/azure-verifier/src/server.js with a **new protocol/profile**, implemented in a new visual-verification module. This operation owns bounded visual evidence for the supplied exact capture; the application composes it with speech, reference and official Face authority. This avoids a second ASR implementation and packaging API/config dependencies into the src-only broker image.

Requests contain server-authored request/attempt ID, fresh 16-byte broker nonce/time, issued contract hash, profile hash, exact capture descriptor, and the authenticated Face proof/reference commitments needed by the selected visual method. Do not send an expected phrase to an acoustic recognizer. Responses authenticate request nonce, request body digest, capture SHA, contract/profile, operation version and returned typed evidence. Reject unknown fields, unsupported profiles, missing bindings and invalid signatures before interpreting status. Existing broker replay maps are per process and expire; DB lease/attempt CAS remains the cross-instance authority. An old signed response from the same challenge must not satisfy a newly issued request by request_id alone.

Required visual evidence is not just a boolean: capture SHA; admitted complete video timeline/stream; observation coverage; detected subject count and track identity; measured match to the independently verified subject; audio/video timing and active-speaker measurements; replay/manipulation evaluation method/version; observed model revisions; decision profile and evidence digest. Exact units and missing-value categories belong in the versioned schema. No existing module supplies this complete result.

There are two legitimate ways to obtain the missing Face-to-recording edge:

1. Prefer a bounded capability evaluation of the gated Azure Face SDK: establish whether its supported integration can expose/commit the exact video payload and contemporaneous audio used by the application, with an authenticated service result covering the same capture timeline. Require documented or provider-confirmed payload/digest semantics and an actual substitution test. A JS callback, shared device ID or two getUserMedia calls is insufficient. If supported, replace the separate Quick Link/MediaRecorder sequence with that one capture contract, retaining server result retrieval and provider-session deletion.
2. If the SDK cannot provide that binding, retain official Face as proof about its own verified subject/session and implement a separate continuous phrase-video verifier: match a server-derived face track to that subject/ID, prove the speaking face corresponds to the canonical audio, and measure replay/manipulation resistance. Reuse the bounded capture decoder infrastructure, but introduce the necessary tracking/active-speaker/anti-spoof models and acceptance pack explicitly. A sampled still-frame match can be a prerequisite, not the entire result. Do not label this second recording as the recording Azure Face certified.

Deleting the prior Face session later, moving it earlier, or setting capture_binding because ASR used the video's audio does not close this edge. Session image retrieval can help compare identity, but a still image does not establish the later phrase's audio producer or liveness. Do not retain raw provider media indefinitely while waiting for an unsupported feature.

## Stage 3: final composition, authority and source replacement

Define a new typed result with independent states for official Face, primary speaker match, spoken nonce/phrase, capture-to-audio ancestry, visible-person/audio continuity and replay/manipulation evidence. Each is measured, rejected, or unavailable with a named cause. Do not fill absent numbers with 0/1, and do not reuse current synthetic_risk_score as 1-cosine or an ASR confidence. Full acceptance requires the complete registered profile and calibrated methods; the older .85/.02 values do not become valid merely because a service emits them.

Extend the real lease, sweep and settlement together. Revalidate issued contract/hash, exact challenge expiry, current policy, active source-bound capture/storage and narrow comparison grants, current primary selection/evidence hashes, ID source/case, Face result snapshot, scanner receipts, exact verifier version/attempt and live lease. Typed decision validation must recompute acceptance from the immutable facts; a content-free key whitelist plus caller-supplied passed boolean is insufficient. Do not release a profile capable of passed settlement before this contract exists.

Review concurrent source deletion, reference retirement/reselection and consent withdrawal with a common lock order. A snapshot EXISTS predicate or FOR UPDATE OF ch alone does not serialize every mutable authority. Choose short locked settlement with post-wait comparisons or explicit NOWAIT/retry behavior, then prove it against the actual counterpart mutation. Never hold those DB locks across provider work.

Also bind downstream build authority to the accepted primary/reference commitment. Current primary setters at _replica-source.js:375-405 and _replica-build-intent.js:232 can replace the reference without recording an equivalent new voice-ownership result. For the first-enrollment slice, refuse stale ownership at build if the primary differs. A later candidate-replacement flow needs an explicitly candidate-bound challenge before its voice can inherit acceptance; do not let an old identity timestamp authorize arbitrary new primary audio. This is necessary to retain the promised primary enrollment ownership boundary, not just a check during one verifier request.

Age remains the independent document-review authority. Do not infer it from Face or voice. Failure/incomplete outcomes preserve honest retry/reissue and bounded raw erasure. Successful activation, identity grant creation and final deployment are separate authorized acceptance work, not artifacts of this design.

## Test contracts and external evidence

- Actual composer: capture A yields canonical A to both speaker and ASR; independent valid WAV B has no influence. Swapped signed derivative, model revision, input stream, locale, primary evidence or contract fails before a verdict. Remove each binding in a source mutant to demonstrate the negative control.
- Actual service routing/auth: v1 remains explicit; new route needs nonce/time and correct protocol; malformed signatures, replay, cross-attempt signed responses, restart/multiple-worker replay and expired private URLs refuse. Cold wake precedes short-window signature issuance. No fake accepted response when a dependency is absent.
- Real local decoder fixtures: WebM/Opus and supported MP4/AAC, malformed/multiple streams, silence, frame-limit boundary and over-limit AAC padding. Preserve existing identity-audio tests and ordinary ASR/processing behavior. Local fixtures do not establish model quality.
- Actual dev SQL: EXPLAIN and execution of every changed issue/read/lease/settle/expiry/cancel shape. Witness consent revocation and replacement grant, primary reselection/removal, reference evidence retirement, Face proof change, policy/locale change, expiry, lease replacement and source erasure while measurement runs. Use manifested fixtures, original-statement mutants where applicable, and full recount cleanup.
- Face/voice adversarial pack: live authorized owner, impostor against owner's primary, stale owner recording with wrong/fresh nonce, stitched speaker change, off-screen reader, dubbed genuine Face video, live face with replayed audio, synthetic voice/video, multiple faces and disrupted A/V timing. Measure each attack class and false rejection by supported locale/device, actual model revision and registered threshold. Set n and acceptance targets before running; none is invented here.
- Deployment/capability evidence still needed: exact voice-evidence image with identity_audio_v1 and observed speaker revisions; actual broker route/config/readiness; native scanner/signature health; Face limited-access approval and supported SDK binding or a real independent visual verifier; document review authority; reference-model compatibility; registered audio/visual acceptance results. Signed responses are provenance, not proof of error rate.

## Official source ledger, checked 2026-09-07

1. [Microsoft Face liveness tutorial](https://learn.microsoft.com/en-us/azure/ai-services/face/tutorials/liveness): the gated SDK controls camera capture and sends its liveness payload; the server retrieves the decision and deletes the session. It documents reference-image face verification, not a guarantee about a separately recorded microphone clip. The latter limitation is this audit's inference about the documented scope, not a claim that every gated SDK capability was inspected.
2. [Microsoft liveness audit schema](https://learn.microsoft.com/en-us/rest/api/face/liveness-session-operations/get-liveness-with-verify-session-audit-entries?view=rest-face-v1.2-preview): digest is the service-calculated request digest, verifyImageHash is the reference image SHA, and targets include file/time offset. These fields must not be renamed a later video's SHA or a joint audio/face identity guarantee.
3. [Microsoft short-audio Speech REST contract](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-speech-to-text-short): direct audio requests have a 60-second maximum and support 16 kHz mono PCM WAV. The application's 30-second identity capture contract is stricter. This is speech recognition, not speaker identity or anti-spoof evidence.

Reversal condition: choose a different architecture only if it proves exact issued source/reference/consent authority and one-recording speech/visual binding with fewer independently maintained components. A nominal endpoint returning all old keys is not that evidence. Recommended immediate scope is Stage 1 plus strict broker protocol/route contracts and tests; calibrated visual acceptance and final grant wiring remain explicit subsequent slices.

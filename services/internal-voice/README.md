# Internal owner voice

The signed-in Studio calls `/api/internal-voice`. This private lane uses the owner's explicitly bound reference and one fixed Hindi utterance through the existing Chatterbox adapter. It does not create identity, consent, generation or genome database rows. Its purpose receipt says `internal_owner_voice`, `identity_scope=owner_asserted_internal`, `release_eligible=false`, `identity_claim_allowed=false`, and `training_allowed=false`. No public enrollment readiness changes.

For the retained reference SHA52a4a5fa05b293de8f99e6529f3d69d94fd9f0cafdcf7ca39985b76eda70b30c, the internal attempt reproduces the historical hi-lesson identity-anchor style (exaggeration0.2, CFG0.78, temperature0.6) and seed41001 recorded by the retained Aug29 runner. The historical same-reference receipt supports `mixed` only at `source_transcript` scope. The queued run and output receipt retain that limited attribution, evidence file SHA256 values, seed provenance and baseline WAV hash. They explicitly deny exact-reference language verification. Different reference hashes receive no inherited transcript claim. These settings are internal only; public preview defaults are unchanged.

## Run contract

GET `?replica_id=<uuid>` returns `enabled`, `scope`, `reference` (label, measured duration, available), `can_generate`, and latest `run`. GET can also select `run_id`. It never probes GPU readiness. POST `{action:'generate',replica_id,run_id:<client UUID>}` creates one durable attempt and returns 202 immediately. The CPU process executes it asynchronously. Repeating the UUID reads the same attempt; an uncertain/crashed attempt never restarts automatically. Default maximum is one attempt per operator-bound authorization namespace.

Poll GET to ready/failed/unknown. A ready run has authenticated same-origin `playback_url`; `reference_url` plays the exact saved reference. Fetch audio with the existing bearer session and create a browser Blob URL. POST `action:'rate'` with the same identifiers and `ratings:{owner_likeness,naturalness,indian_accent,pronunciation}` integer 1..5; POST `action:'revoke'` revokes playback/dispatch and deletes the generated WAV. Reference remains the existing authorized test asset. Expired authorization blocks generation, ratings and playback; owner revoke remains available. Operator erasure of the authorization Blob prefix removes the retained reference and receipts when that test authorization is retired.

Run metrics contain actual provider elapsed milliseconds, PCM duration, total wall time and provider real-time factor. `first_audible_ms` is null until the browser measures playback, never guessed. Ratings are owner observations, not calibrated likeness scores. No real synthesis or quality claim follows from the offline tests.

## CPU deployment and credentials

Build **from repository root**, Dockerfile `services/internal-voice/Dockerfile`, with an explicitly reviewed immutable Node 24 `NODE_IMAGE` build argument. The positive COPY list includes 25 files; it excludes ignored `api/_config.js`, tests, model weights, local recordings, and credentials. No npm install or GPU image rebuild is involved.

Run `node services/internal-voice/server.mjs serve` on port 8080 (or `PORT`). Run `node services/internal-voice/supervisor.mjs` as an independent persistent CPU process using the same image/configuration. The supervisor must continue while an attempt is running and during cleanup; do not use an HTTP-scaled-to-zero process for this responsibility. It commits a 30-second heartbeat every five seconds and independently observes/deactivates the exact existing GPU revision at the 420-second dispatch deadline. A lost/uncertain ARM mutation is retained, not replayed. Nine hundred seconds is a planning envelope, not a hard invoice bound. Root may run the supervisor on an existing protected CPU/operator host for the first experiment rather than create another service.

Both CPU processes require:

- `VYAKTI_INTERNAL_VOICE_MODE=owner-only`, `VYAKTI_MODEL_SERVING=azure_only`, exact `VYAKTI_INTERNAL_VOICE_OWNER_USER_ID` and `VYAKTI_INTERNAL_VOICE_REPLICA_ID`; `REPLICA_SELF_TEST_MODE` unset/false and `REPLICA_SELF_TEST_ACCESS` unset.
- `VYAKTI_INTERNAL_VOICE_AUTHORIZATION_JSON` and `VYAKTI_INTERNAL_VOICE_AUTHORIZATION_SHA256` (SHA256 of exact UTF-8 JSON bytes); `VYAKTI_INTERNAL_VOICE_MAX_ATTEMPTS=1`.
- `AZURE_VOICE_APP_ENABLED=true`, `AZURE_VOICE_APP_PLAN_JSON`, `AZURE_VOICE_APP_POLICY_JSON`, `AZURE_VOICE_APP_APPROVAL_SHA256=commitment({plan,policy})`, using the unchanged controller schema. Policy `supervisor_source_sha256` is SHA256 of the committed supervisor.mjs bytes. Pricing must be supplied from reviewed billing evidence; the code does not assert a dollar cap.
- `AZURE_OPEN_VOICE_ORIGIN` is the exact chosen public CPU broker; `OPEN_VOICE_MODEL_ARM=hindi_v3`; `OPEN_VOICE_HMAC_SECRET` matches broker and GPU runtime.
- Existing private Azure Blob `AZURE_REPLICA_STORAGE_ACCOUNT`, `AZURE_REPLICA_STORAGE_ACCOUNT_KEY`, `AZURE_REPLICA_STORAGE_CONTAINER`. All durable state/WAVs live under `<owner>/<authorization_id>/internal-voice/`. Updates use Azure Blob ETag conditional writes; generated audio is create-only. No filesystem/shared-mount assumptions.
- Managed identity `IDENTITY_ENDPOINT` and `IDENTITY_HEADER`, optional `AZURE_VOICE_APP_IDENTITY_CLIENT_ID`, with read and exact revision activate/deactivate authority on the selected existing GPU app. For a bounded operator run, `VYAKTI_INTERNAL_VOICE_ARM_TOKEN` can instead hold a current ARM bearer token; it is never logged. The independent supervisor needs the same resource authority. No create, scale or GPU warm action is implemented.

The HTTP server additionally needs `SUPABASE_URL` and `SUPABASE_KEY` to verify the forwarded bearer session directly with Supabase. `/healthz` reports CPU liveness only. Its allocation callback reuses the existing HMAC admission handler, backed by the internal Blob child consumer rather than the public-enrollment SQL predicate.

Vercel needs only the four internal mode/owner/replica/Azure-only variables above, `VYAKTI_INTERNAL_VOICE_ORIGIN=https://<CPU service>.azurecontainerapps.io`, existing Supabase auth and the legacy self-test flags off. It does not get Blob or ARM credentials and holds no durable state.

Authorization JSON shape (operator supplies actual values; do not commit it): `authorization_id`, `scope:'internal_owner_voice'`, `owner_user_id`, `replica_id`, `reference_sha256`, `expires_at` as a future ISO timestamp, `identity_claim_allowed:false`, `release_eligible:false`, `training_allowed:false`, and exact ordered `purposes:['reference_processing','zero_shot_synthesis','private_playback','owner_ratings']`. This records the owner's internal-use instruction, not third-party identity verification.

Prime once from the protected operator host with `VYAKTI_INTERNAL_VOICE_REFERENCE_PATH` pointing at the retained owner WAV: `node services/internal-voice/server.mjs prime`. It verifies SHA256 and canonical 24 kHz mono PCM16 signal/duration, then conditionally uploads reference bytes and measured descriptor to the existing private container. It makes no provider call. Clear the path afterward. Lost prime acknowledgement needs operator inspection; it is not overwritten.
